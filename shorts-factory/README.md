# 쇼핑쇼츠 자동 생산 공장

매일 10개(채널 5개 × 2개)의 쇼핑 쇼츠를 자동 생성해 **승인 대기 상태로** 올려둔다.
배포는 대시보드에서 승인 버튼을 눌러야 나간다.

파이프라인을 긴 스크립트 하나로 두지 않고, **전문성 하나씩 맡은 담당자들이 작업물을
넘겨가며 완성하는 팀**으로 구성했다. 코드는 `src/team/` 에 있다.

```
npx tsx src/stage.ts team     팀 구성 출력
npx tsx src/stage.ts daily    오늘치 제작 (승인 대기까지)
npx tsx src/stage.ts publish  승인된 것만 배포 (--run-id 생략 시 최근 승인 대기 run)
npx tsx src/stage.ts metrics  성과 수집
npx tsx src/stage.ts report   성과 요약
```

## 팀 구성

**제작 라인** (`src/team/index.ts` 의 `PRODUCTION_LINE`) — 영상 한 편은 이 순서로 손을 거친다.

| 담당자 | 파일 | 맡은 것 |
|---|---|---|
| 소싱 담당 `scout` | `members/scout.ts` | 틱톡 **인기순**을 훑어 이미 터진 영상에서 상품과 레퍼런스를 한 번에 확보. 중국어 검색어 변형까지 만들어 넘긴다 |
| 소재 담당 `sourcer` | `members/sourcer.ts` | 그 중국어 검색어로 **해외 원본** 영상 확보. 모자라면 1688 상품 상세 영상으로 보강 |
| 구조 분석가 `analyst` | `members/analyst.ts` | 원본에서 **골격만** 추출 — 훅 유형, 컷 배치, 설득 순서. 대사도 화면도 가져오지 않는다 |
| 카피라이터 `writer` | `members/writer.ts` | 설계도 구조를 지키면서 한국어 구어체로 각색. 문어체가 섞이면 최대 3회 재작성 |
| 성우 연출 `voice` | `members/voice.ts` | 타입캐스트 문장별 합성. 속도·끊어읽기 조율 |
| 편집자 `editor` | `members/editor.ts` | 컷에 소재 배정 → 잘라 이어붙이기 → 자막·나레이션 합성 |
| 품질 검수 `qa` | `members/qa.ts` | 완성본 하나를 놓고 길이·규격·싱크 판정. 승인 큐에 올릴 자격을 본다 |

**라인 밖** — 시점이 달라 따로 돈다.

| 담당자 | 파일 | 맡은 것 |
|---|---|---|
| 유통 담당 `publisher` | `members/publisher.ts` | 사람이 승인한 뒤 업로드 + 제휴 링크 부착. 업로드 시각을 렌더별로 흩뿌린다 |
| 성장 분석 `growth` | `members/growth.ts` | 배포 며칠 뒤 성과 집계. 어떤 훅이 **돈이 됐는지**로 다음 선택을 조정 |

### 왜 팀 구조인가

1. 각 담당자가 자기 영역의 판단 기준만 알면 된다 → 업무 헌장(`charter`, 곧 LLM 시스템
   프롬프트)이 짧고 정확해진다
2. 자기 결과물을 자기가 검수한다 → 불량이 다음 공정으로 안 넘어간다
3. 인수인계 메모가 남는다 → 결과물이 왜 이렇게 나왔는지 역추적된다

### 인수인계와 자기검수

지시서 한 장(`Brief`, `src/team/types.ts`)이 라인을 따라 내려가며 채워진다.
담당자마다 `work()` → `review()` 순으로 돈다.

- `work()` 는 자기 구간을 수행하고 **인수인계 메모**(`HandoffNote`)를 붙인다.
  다음 담당자가 알아야 할 것은 `message`, 판단이 갈릴 수 있었던 지점은 `caveat` 로 남긴다.
  카피라이터가 분석가의 흐름 메모를 재료로 쓰는 것처럼, 메모는 기록이 아니라 입력이다.
- `review()` 는 자기 산출물을 자기 기준으로 판정한다. 불합격(`problems`)이면
  `HandoffError` 로 **그 건만** 중단되고 나머지 슬롯은 계속 간다. 하루치가 통째로
  날아가는 것보다 8편이라도 올라가는 편이 낫다.
- 품질 검수만 예외다. 자기 판정을 다시 뒤집지 않고, 검수 실패여도 라인을 멈추지 않는다.
  대신 `qc_passed = false` 로 남겨 **일괄 승인에서 빠지고** 사람이 개별 확인하게 한다.
  앞 공정의 `caveat` 가 2건 이상 쌓여도 같은 판정을 내린다.

어느 담당자에게서 자주 막히는지가 다음에 손볼 곳이다. `daily` 실행 끝에
담당자별 실패 횟수가 출력된다.

## 타겟 시청층 프로파일

`src/lib/audience.ts`. **같은 쇼핑 쇼츠라도 누가 보느냐에 따라 최적 파라미터가 정반대로 간다.**
채널 설정의 `audience` 한 줄이 라인 전체의 동작을 바꾼다.

|  | `senior` (50~70대) | `general` (10~40대) |
|---|---|---|
| 나레이션 속도 | 1.25배 | 1.1배 |
| 소스 재생 속도 | 1.3배 | 1.0배 |
| 컷 개수 | 3~5개 (컷당 최소 3.5초) | 5~9개 (컷당 최소 2.5초) |
| 자막 | 96px · 외곽선 7 · 한 줄 12자 | 72px · 외곽선 5 · 한 줄 16자 |
| 한 문장 | 10~16자 | 12~18자 |
| 화법 | 자기 경험 섞은 스토리텔링, 한 문장에 정보 하나, 외래어 금지 | 첫 1.5초에 결론, 정보 밀도 높게 |

틱톡 라이트 친구초대 이벤트로 시니어가 대거 유입되면서 생긴 시장 특성이다.
실무적으로 중요한 이유: **시니어 타겟이면 제작 난이도 자체가 내려간다.**
컷을 적게 쓰고 전환을 줄여도 되니 소재도 덜 필요하고 렌더도 단순해진다.
그래서 `PLATFORM_DEFAULT_AUDIENCE` 는 틱톡·네이버 클립을 `senior` 로 둔다.

느리게 간다는 뜻은 아니다. 타입캐스트 기본 속도가 워낙 느려서, 시니어 대상도
1.25배로 **올려야** 끝까지 본다.

## 설계상 양보하지 않는 것

- **`MAX_CLIP_SEC = 5`** — 소스 클립당 사용 길이 상한. 공정이용 근거가 "각 영상에서
  3~5초만" 이라, `ffmpeg.trimToPortrait` 이 이를 넘는 요청을 **거부한다.**
  설계도가 더 긴 컷을 요구해도 거기서 막힌다. 우회 경로를 만들지 않는다.
  소재가 적으면 소스당 사용 길이가 이 상한에 걸리므로, 소재 담당이
  `MIN_SOURCE_COUNT` 미만에서 먼저 멈춘다.
- **승인 게이트** — 제작 라인은 품질 검수에서 **끝난다.** 배포는 사람이 대시보드에서
  승인한 뒤 `publish` 가 따로 돈다. 유통 담당은 `approval_status = 'approved'` 인
  렌더만 조회한다.
- **실패를 삼키지 않는다** — 미구현 업로드 경로는 조용히 성공한 척하지 않고 명시적으로
  던진다. 링크 부착이 실패하면 업로드 기록은 남기되 `link_status = 'manual_required'`
  로 큐에 올린다. 링크가 안 붙은 영상은 수익이 0이라 반드시 사람에게 보여야 한다.
  전부 실패하면 프로세스가 0이 아닌 코드로 죽어 CI가 빨개진다.

## 샤오홍슈 · 1688 접근 — 왜 이 한 조각만 파이썬인가

파이프라인은 전부 TypeScript 인데 `scrapers-py/cn_media.py` 만 파이썬이다. 취향이 아니라
실측 결과다.

**막힌 방법** — 헤드리스 크롬(Playwright)으로 재생 페이지를 열어 미디어 응답을 가로채기:

- 샤오홍슈 검색 페이지가 「로그인 후 검색결과 보기」로만 렌더된다. 검색 API 호출 자체가
  일어나지 않으므로 가로챌 응답이 없다.
- 게스트 쿠키를 받아 페이지 컨텍스트의 서명 함수로 직접 호출해도 `code -104` (권한 없음).
- 타오바오에서는 상품 영상을 **한 건도** 받지 못했다.

**통한 방법** — 브라우저를 아예 안 쓴다:

- `curl_cffi` 로 크롬 TLS 지문을 흉내 내 SSR HTML 을 받고, 그 안의
  `window.__INITIAL_STATE__` JSON 을 파싱한다. 로그인도 쿠키도 필요 없다.
- 1688 은 더 쉽다. 상품 상세 HTML 에 영상 주소가 그대로 박혀 있다.

node 에는 크롬 TLS 지문을 흉내 내는 검증된 수단이 없어서 그 조각만 파이썬 프로세스로
떼어내고 `src/lib/scrapers/cn-bridge.ts` 가 호출한다.

### 그래서 포기한 것

| | 되는 것 | 안 되는 것 |
|---|---|---|
| 샤오홍슈 | `/explore` 피드(1회 ≈27건), 노트 상세(영상·좋아요·수집) | **키워드 검색** (로그인 벽), 계정별 노트 목록 |
| 1688 | 홈·상세 페이지 | **상품 검색** (아래 실측) |

### 실측 기록 (2026-09-20, GitHub 러너)

네트워크가 열린 곳에서 실제로 재본 값이다. 추측과 구분하려고 숫자를 남긴다.

| 대상 | 결과 |
|---|---|
| 샤오홍슈 SSR | HTTP 200, **182,976바이트, `__INITIAL_STATE__` 있음** — 로그인·쿠키 없이 통과 |
| 샤오홍슈 피드 | 1회 호출에 **27건**. 특정 키워드를 맞히기엔 모수가 작아 여러 번 부른다 |
| 1688 홈 / 상세 | 90KB / 13KB — **열린다** |
| 1688 검색 (5개 진입로) | 25KB 수신, 그러나 `detail.1688.com/offer` 링크 0건, `offerId`·`data-offer-id` 0건 |

1688 검색 페이지에는 **상품 데이터가 아예 없다.** 캡차도 로그인 벽도 아니고, HTML 은
껍데기이며 JS 가 나중에 목록을 받아온다. 그래서 HTTP 만으로는 1688 검색을 뚫을 수 없다 —
상품 id 를 다른 데서 구해 상세만 여는 경로가 필요하다.

한 가지 더: 1688 은 연속 요청을 맞으면 **HTTP 200 으로 1KB 대 조각**을 돌려준다.
영구 차단으로 오해하기 쉬운데 잠깐 쉬면 같은 URL 이 25KB 를 준다. `get_html` 이
간격을 벌려 3회까지 다시 친다.

샤오홍슈는 **검색을 못 한다.** 입구가 `/explore` 피드뿐이라 키워드는 피드에 뜬 노트의
캡션을 거르는 데만 쓴다. 그래서 니치한 상품일수록 0건이 나오고, 그건 "레퍼런스가 없다"가
아니라 "이번 피드에 안 떴다"이다. 둘을 같은 빈 배열로 돌려주면 위에서 판단을 잘못하므로
`FeedMissError` 로 구분해 던진다.

`xsec_token` 은 **게시물마다 다르다.** 피드에서 받은 토큰을 그 노트에만 써야 하고
돌려쓰면 열리지 않는다. 그래서 피드 → 상세를 한 흐름 안에서 잇는다.

### 파싱 함정 둘

`__INITIAL_STATE__` 는 JSON 이 아니라 JS 리터럴이다. 값이 비면 `null` 이 아니라
`undefined` 가 들어가 `json.loads` 가 그대로 터지고, Vue ref 가 직렬화돼 있어 실제 값이
`_rawValue` 한 겹 아래에 있다. 둘 다 `test_cn_media.py` 가 고정해둔다 — 여기가 깨지면
소싱이 통째로 0건이 되므로 네트워크 없이 매번 검증한다.

## Phase 0 체크리스트

공장을 다 짓고 여기서 막히는 게 가장 흔한 실패다. 먼저 확인한다. (`src/probe.ts`)

- [ ] **타입캐스트 API** — 문장별 오디오 *길이* 를 응답에서 받을 수 있는가?
      못 받으면 자막 싱크 전략이 무너진다. 하루 50~70콜이 플랜 한도에 들어가는가?
- [ ] **YouTube API 감사** — 감사 미통과 프로젝트의 API 업로드는 비공개로 고정되고
      공개 전환이 불가능하다. 즉시 신청하고, 테스트 채널에 1건 올려 **직접 확인**한다.
- [ ] **틱톡 인기순 탐색** — 소싱 담당이 여기서 상품과 레퍼런스를 동시에 얻는다.
      막히면 제작 라인이 첫 담당자에서 멈춘다. 가장 먼저 뚫어야 할 항목.
- [ ] **틱톡 중국어 검색 / 1688** — 소재 담당의 1차·2차 경로. 해외 원본 영상이
      실제로 잡히는가. 한국 영상은 소재로 쓰지 않으므로 대체재가 없다.
      `npm run probe` 의 `cn-bridge` 점검이 먼저 통과해야 나머지가 의미가 있다.
- [ ] **업로드 셀렉터 맞추기** — 네이버 클립·틱톡 업로더의 `SELECTORS` / `URLS` 는
      실물 DOM 으로 검증되지 않았다. `HEADFUL=true` 로 한 번 띄워 눈으로 맞춘다.
- [ ] **네이버 클립** — 구독자 조건 없이 구매 링크 스티커가 붙는 유일한 채널이라
      가장 먼저 자동화할 가치가 있다. 스티커가 안 붙으면 이 채널을 돌릴 이유가 없다.
- [ ] **틱톡 사업자 인증** — 인증을 마치면 팔로워 0명부터 틱톡샵 링크가 붙는다.
      유튜브의 "90일 내 쇼츠 300만뷰" 와 비교하면 진입 장벽이 사실상 없다.
- [ ] **인포크링크 / 텐핑** — 링크 자동 생성이 되는가? 안 되면 자체 리다이렉터
      (`dashboard/app/go`) 로 대체한다.

| `TIKTOK_STORAGE_STATE` | 틱톡 세션 JSON. 소싱·소재 담당의 탐색과 틱톡 업로드가 함께 쓴다 |
| `INSTAGRAM_STORAGE_STATE` | 인스타 세션 JSON |
| `XHS_EXPLORE_CHANNELS` | 선택 — 샤오홍슈 피드에서 훑을 카테고리 채널 id (쉼표 구분). 비우면 기본 피드만 본다 |
| `XHS_FEED_SCAN_LIMIT` | 선택 — 피드를 한 번에 몇 건까지 훑을지 (기본 `60`) |
| `PYTHON_BIN` | 선택 — `python3` 이외의 경로를 쓸 때만 |
| `NAVER_STORAGE_STATE` | 네이버 클립 업로드용 세션 JSON |
| `NAVER_CLIP_UPLOAD_URL`, `NAVER_CLIP_EDIT_URL`, `TIKTOK_UPLOAD_URL`, `TIKTOK_CONTENT_URL` | 업로드 화면 URL 이 바뀌었을 때만 (선택) |
| `YOUTUBE_CREDENTIALS_*` | 채널별 OAuth (`{client_id, client_secret, refresh_token}`) |
| `TIKTOK_BUSINESS_VERIFIED` | `true` 면 팔로워 수와 무관하게 틱톡샵 링크 모드 |
| `MIRROR_FOOTAGE` | `true` 면 소재를 좌우 반전. 중복 판정 회피 목적이라 기본값은 끔 |
| `ZOOM_FOOTAGE` | 소재 확대 비율 (기본 `1.1`). 가장자리 워터마크를 프레임 밖으로 민다 |
| `REDIRECTOR_BASE_URL` | 클릭 추적 리다이렉터 도메인 (선택) |
| `HEADFUL` | `true` 면 브라우저를 눈에 보이게 띄운다. 셀렉터 맞출 때만 |
| `FFMPEG_PATH`, `FFPROBE_PATH` | PATH 에 없을 때만 |

## 자주 만지는 설정

전부 `src/config.ts` 에 있다.

- `CHANNELS` — 채널 5개의 플랫폼·카테고리·보이스·**타겟**. 플랫폼을 섞어두면 중복 콘텐츠
  판정이 구조적으로 불가능해진다. `audience` 한 줄이 대본 화법·나레이션 속도·컷 개수·
  자막 크기를 전부 바꾼다.
- `MAX_CLIP_SEC`, `MIN_SOURCE_COUNT` — 공정이용 제약. 위의 "양보하지 않는 것" 참고.
- `COOKIE_DAYS_CAP`, `IMPULSE_PRICE_RANGE` — 상품 점수 튜닝.
- `UPLOAD_JITTER_MINUTES` — 업로드 시각 분산 폭.
- `MODELS` — `reasoning` / `fast` 두 자리. 담당자마다 어느 쪽을 쓰는지는 각 멤버가 정한다.

## 알려진 미구현

- 인스타 업로드 (`lib/publishers/` — 현재 명시적으로 에러를 던진다)
- 네이버 클립 · 틱톡 업로드는 Playwright 로 구현돼 있으나 **셀렉터가 미검증**이다.
  각 파일 상단의 `SELECTORS` / `URLS` 를 Phase 0 에서 `HEADFUL=true` 로 띄워 맞춰야 한다.
  두 채널 모두 예약 게시는 자동화하지 않았다 (즉시 게시된다).
- 틱톡샵 상품 링크 (셀러 계정 흐름 필요 → 현재 명시적으로 에러를 던진다)
- 유튜브 쇼핑 상품 태그 (공개 API 없음 → Studio 브라우저 자동화 필요)
- 타입캐스트 웹 자동화 폴백 (API 가능 여부 확인 후 판단)
- 성장 분석의 **플랫폼별 지표 수집** — 지금은 리다이렉터가 기록한 클릭뿐이고 조회수·수익
  수집은 스켈레톤이다. 이게 비면 피드백 루프가 닫히지 않는다.
  켜도 채널마다 따로 만든다.
- **다중 플랫폼 레퍼런스 발굴** — 샤오홍슈·인스타 스크래퍼(`lib/scrapers/`)와
  `REFERENCE_QUOTA` 는 남아 있지만 제작 라인은 쓰지 않는다. 소싱 담당이 틱톡 인기순
  하나로 상품과 레퍼런스를 동시에 얻는 쪽이 빠르고 정확해서다.
  두 스크래퍼는 `src/probe.ts` 가 계속 점검한다.
